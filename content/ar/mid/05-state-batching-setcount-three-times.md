# لماذا يؤدي استدعاء setCount(count + 1) ثلاث مرات متتالية إلى زيادة 1 فقط؟

**Level:** Mid
**Merged from (original phrasings):**
- لماذا يضيف استدعاء setCount(count + 1) ثلاث مرات في معالج أحداث واحد 1 فقط بدلاً من 3؟

## The concept
- قيمة `count` هي **لقطة ثابتة (Constant Snapshot)** خاصة بدورة التصيير (Render) الحالية. داخل معالج الأحداث تكون قيمتها، على سبيل المثال، `0` طوال وقت التنفيذ. لذلك فإن استدعاء `setCount(count + 1)` ثلاث مرات متتالية هو في الحقيقة استدعاء لـ `setCount(1)` ثلاث مرات متطابقة.
- دالة `setState` لا تغير قيمة المتغير فوراً بشكل تزامني، بل **تضع طلب التحديث في طابور (Queue)** وتطلب من React جدولة إعادة التصيير. القيمة الجديدة لن توجد إلا في **دورة التصيير التالية**.
- يقوم React **بتجميع التحديثات (Batching)** الناتجة عن نفس الحدث في عملية إعادة تصيير واحدة (وفي React 18+ أصبح هذا التجميع تلقائياً في كل مكان: معالجات الأحداث، والمؤقتات، والـ Promises، ومستمعي الأحداث الأصليين).
- الحل: استخدم **دالة التحديث (Updater function)** بالشكل التالي: `setCount(c => c + 1)`. يشغل React دوال التحديث المصطفة بالترتيب، وتستلم كل واحدة منها النتيجة المحسوبة من الدالة السابقة: 0 -> 1 -> 2 -> 3.
- قاعدة ذهبية: إذا كانت الحالة الجديدة تعتمد على الحالة السابقة، فاستخدم دائماً صيغة دالة التحديث (Updater form).

```js
// معالجة طابور التحديثات لدورة تصيير واحدة:
setCount(count + 1); // استبدال بالقيمة 1
setCount(count + 1); // استبدال بالقيمة 1
setCount(count + 1); // استبدال بالقيمة 1   -> النتيجة النهائية: 1

setCount(c => c + 1); // 0 -> 1
setCount(c => c + 1); // 1 -> 2
setCount(c => c + 1); // 2 -> 3          -> النتيجة النهائية: 3
```

## Real-life example
في صفحة الدفع لخدمة توصيل البقالة، يستدعي زر "+" بجانب العنصر دالة `addOne()`. طلب فريق المنتج إضافة زر "+3 bundle" لإضافة 3 حبات معاً، فقام المطور ببساطة باستدعاء الدالة ثلاث مرات، مع إضافة ميزة الإضافة السريعة عند النقر المزدوج. تفاجأ العملاء بأن النقر على "+3" يغير الكمية من 2 إلى 3 فقط وليس إلى 5! ومع النقر السريع، يتأخر العداد كثيراً عن نقرات المستخدمين. كما تسبب هذا الخلل في مشكلة خفية أخرى: سجل التحليلات (Analytics) يسجل **القيمة القديمة** للكمية بدلاً من القيمة الجديدة.

```jsx
function CartItem({ item }) {
  const [qty, setQty] = useState(item.qty);

  const addOne = () => {
    setQty(qty + 1);
  };

  const addBundle = () => {
    addOne();
    addOne();
    addOne(); // قيمة qty لا تزال 2 في الاستدعاءات الثلاثة -> النتيجة 3 فقط
    track('bundle_added', { qty }); // يسجل 2: القيمة القديمة من اللقطة الحالية، وليس القيمة الجديدة
  };

  return (
    <div>
      <span>{qty}</span>
      <button onClick={addOne}>+</button>
      <button onClick={addBundle}>+3 bundle</button>
    </div>
  );
}
```

## How to fix it
```jsx
function CartItem({ item }) {
  const [qty, setQty] = useState(item.qty);

  const add = (n = 1) => {
    setQty((q) => Math.min(q + n, item.maxQty)); // دالة التحديث: تستخدم دائماً أحدث قيمة في الطابور
  };

  const addBundle = () => {
    const next = Math.min(qty + 3, item.maxQty); // احسب القيمة الجديدة في متغير محلي إذا كنت بحاجة إليها فوراً
    setQty(next);
    track('bundle_added', { qty: next });
  };

  return (
    <div>
      <span>{qty}</span>
      <button onClick={() => add(1)}>+</button>
      <button onClick={addBundle}>+3 bundle</button>
    </div>
  );
}
```
سبب نجاح الحل:
- دالة التحديث `q => q + n` لا تقرأ قيمة `qty` القديمة المحبوسة في الـ Closure، بل يمرر React أحدث قيمة معلقة لكل دالة تحديث بالتسلسل، وبالتالي فإن ثلاثة استدعاءات لـ `add(1)` ستنتج بشكل صحيح زيادة قدرها `+3`.
- إذا كنت بحاجة إلى القيمة الجديدة داخل نفس المعالج (لإرسال تحليلات أو لطلب API)، **احسبها مسبقاً في متغير محلي (Local variable)** واستخدم ذلك المتغير لكل من `setQty` والعملية الجانبية (Side effect). إياك أن تقرأ الـ State فور استدعاء دالة التحديث الخاصة بها.

حلول بديلة: إذا كانت هناك عدة حقول تتغير معاً (الكمية، والسعر، والخصم)، فاستخدم `useReducer` بحيث تجتمع منطق الحالة في مكان واحد يرى دوماً الحالة الراهنة بدقة. وتستطيع `flushSync` فرض إعادة تصيير تزامنية فورية، ولكن نادراً ما تكون هي الحل الصحيح لأنها تضر بالأداء.

### التجميع التلقائي (Automatic Batching) في React 18+
```jsx
setTimeout(() => {
  setQty((q) => q + 1);
  setLoading(false);
  // في React 17: عمليتا تصيير منفصلتان (لا يوجد تجميع خارج أحداث React المباشرة)
  // في React 18+: عملية تصيير واحدة فقط (تجميع تلقائي في كل مكان)
}, 1000);
```

## How to say it in the interview
- "الحالة (State) هي لقطة ثابتة لكل دورة تصيير. استدعاء `setCount(count + 1)` يستخدم نفس قيمة `count` ثلاث مرات، ويجمع React التحديثات الثلاثة في تصيير واحد فتكون النتيجة +1 فقط. بينما تقوم صيغة دالة التحديث `setCount(c => c + 1)` بتسلسل التحديثات بدقة."
- سؤال متابعة / فخ: "لماذا يطبع `console.log(count)` بعد `setCount` القيمة القديمة؟" لأن متغير `count` في دورة التصيير الحالية لا يتغير أبداً؛ فالقيمة الجديدة لن تظهر إلا في دورة التصيير التالية.
- "يقوم React 18 بالتجميع التلقائي (Automatic Batching) في كل مكان، بما في ذلك المؤقتات والـ Promises. قبل React 18، كان التجميع مقتصراً على معالجات أحداث React فقط."
- الموازنة (Trade-off): يوفر التجميع تقليلاً في عمليات إعادة التصيير وأداءً أفضل بكثير، ولكن يجب ألا تفترض أبداً تحديث الحالة بشكل تزامني. استنتج القيم محلياً في متغير إذا كنت بحاجة لها على الفور.
