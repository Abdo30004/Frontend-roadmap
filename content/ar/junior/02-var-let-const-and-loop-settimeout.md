# ما الفرق بين var و let و const (ولماذا تكسر var حلقة for مع setTimeout)؟

**المستوى:** مبتدئ (Junior)
**Merged from (original phrasings):**
- ما الفرق بين "var" و "let" و "const"؟
- اشرح الفرق بين var و let و const في JavaScript.‏
- ماذا يحدث عند استخدام "var" داخل حلقة "for" مع "`setTimeout()`"؟
- سؤال برمجي: ما ناتج `for (var i = 0; i < 3; i++) { setTimeout(() => { console.log(i); }); }`؟ ولماذا؟ وكيف تصلحه باستخدام let أو closure؟

## The concept (short answer)

| | `var` | `let` | `const` |
|---|---|---|---|
| النطاق (Scope) | نطاق الدالة (Function) | نطاق الكتلة (Block) `{ }` | نطاق الكتلة (Block) `{ }` |
| الرفع (Hoisting) | تُرفع مع قيمة أولية `undefined` | تُرفع، لكنها تظل في **منطقة الخمول الزمني (TDZ)** حتى تنفيذ سطر تعريفها | مثل `let` تماماً |
| إعادة الإعلان في نفس النطاق | نعم | لا (SyntaxError) | لا |
| إعادة التعيين (Re-assign) | نعم | نعم | **لا** |
| الخاصية العامة (`window.x`) | نعم، في المستوى العام (top level) | لا | لا |

- تمنع `const` **إعادة التعيين** فقط، ولا تمنع تعديل محتوى الكائنات أو المصفوفات: `const cart = []; cart.push(item)` كود سليم تماماً.
- محاولة استخدام `let` أو `const` قبل سطر التعريف تؤدي لرمي خطأ `ReferenceError` بسبب الـ TDZ. بينما استخدام `var` قبل تعريفها يعود بـ `undefined`، مما يخفي الأخطاء البرمجية.
- القاعدة الحديثة: استخدم `const` كخيار افتراضي دائم، واستخدم `let` فقط عند الحاجة لتغيير القيمة، وتجنب `var` تماماً.

### السؤال البرمجي في المقابلة

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log(i);
  });
}
```

**الناتج:** `3`, `3`, `3`.‏

**السبب:**
1. تمتلك `var` نطاق دالة (function scope)، لذلك يوجد متغير `i` **واحد فقط** مشترك عبر كامل الحلقة التكرارية.
2. تضع `setTimeout` دوال رد النداء في طابور المهام (task queue). ولا يتم تنفيذها إلا بعد فراغ مكدس الاستدعاءات (call stack) من الكود المتزامن (أي بعد اكتمال تنفيذ الحلقة التكرارية بالكامل)، حتى لو كان التأخير الزمني 0.‏
3. عند انتهاء الحلقة، تكون قيمة `i` قد وصلت إلى `3` (وهي القيمة التي جعلت الشرط `i < 3` خاطئاً).‏
4. جميع دوال رد النداء الثلاث هي closures تُغلق على **نفس** المتغير `i` المشترك، فتطبع جميعها الرقم `3`.‏

**الحل 1: استخدام `let` (الأفضل).** يُنشئ استخدام `let` في ترويسة حلقة `for` **رابطاً جديداً (new binding) لكل تكرار**، بحيث تُغلق كل دالة رد نداء على نسخة `i` الخاصة بها.

```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i)); // 0, 1, 2
}
```

**الحل 2: الـ closure عبر دالة IIFE (الأسلوب المتبع قبل ES6).** ينشئ استدعاء الدالة نطاقاً جديداً بمتغير خاص به `j`.‏

```js
for (var i = 0; i < 3; i++) {
  (function (j) {
    setTimeout(() => console.log(j)); // 0, 1, 2
  })(i);
}
```

**الحل 3: تمرير القيمة كوسيط لدالة `setTimeout`.** يتم تمرير الوسائط الإضافية مباشرة إلى دالة رد النداء.

```js
for (var i = 0; i < 3; i++) {
  setTimeout((j) => console.log(j), 0, i); // 0, 1, 2
}
```

## Real-life example: the problem
تخيّل تطبيقاً لتوصيل الوجبات يعرض شاشة "جارٍ تحضير طلبك" مع 3 مراحل (تم الاستلام، جارٍ الطهي، في الطريق). يجب أن تضيء كل مرحلة تلو الأخرى بفاصل زمني ثانية واحدة. في بيئة الإنتاج، لم يتحرك أي مؤشر لمدة 3 ثوانٍ، ثم ظهر فجأة خطأ `TypeError: Cannot read properties of undefined (reading 'classList')` ثلاث مرات في الـ console، وبقيت المؤشرات باللون الرمادي.

```js
// BROKEN
const steps = document.querySelectorAll('.order-step'); // 3 عناصر

for (var i = 0; i < steps.length; i++) {
  setTimeout(() => {
    steps[i].classList.add('active'); // قيمة i هنا هي 3 -> و steps[3] تساوي undefined
  }, (i + 1) * 1000);
}
```

ملاحظة: التأخيرات الزمنية كانت صحيحة (1s، 2s، 3s) لأن التعبير `(i + 1) * 1000` يتم حسابه **أثناء** تشغيل الحلقة. أما الكود الموجود **داخل** دالة رد النداء فلا يقرأ المتغير `i` إلا لاحقاً، بعد اكتمال الحلقة بالكامل.

## How to fix it

```js
// FIXED
const steps = document.querySelectorAll('.order-step');

for (let i = 0; i < steps.length; i++) {
  setTimeout(() => {
    steps[i].classList.add('active'); // تمتلك كل دالة i خاصة بها: 0، 1، 2
  }, (i + 1) * 1000);
}

// حل ممتاز أيضاً: تمنح forEach كل دالة وسيطاً خاصاً بها
steps.forEach((step, index) => {
  setTimeout(() => step.classList.add('active'), (index + 1) * 1000);
});
```

لماذا ينجح هذا الحل: مع `let`، تنشئ الحلقة التكرارية متغيراً جديداً `i` في كل دورة، وتُغلق كل دالة سهمية على نسختها الخاصة. وتعمل دالة `forEach` بنجاح أيضاً لأن كل استدعاء لدالة رد النداء يمتلك معاملاته الخاصة `step` و `index`.‏

فخ آخر شائع مع `const` يجدر بك معرفته:

```js
const user = { name: 'Ana' };
user.name = 'Bob';   // صحيح: تعديل خاصية داخل الكائن
user = {};           // TypeError: Assignment to constant variable.
// استخدم Object.freeze(user) إذا كنت بحاجة لجعله غير قابل للتعديل (تجميد سطحي فقط).
```

## How to say it in the interview
- "`var` تمتلك نطاق دالة وتُرفع مع قيمة أولية `undefined`؛ بينما `let` و `const` تمتلكان نطاق كتلة وتعيشان في منطقة الخمول الزمني (TDZ) حتى سطر التعريف. وتمنع `const` إعادة التعيين وليس تعديل الكائن."
- بخصوص اللغز البرمجي: "يطبع 3، 3، 3 لأن هناك متغيراً مشتركاً واحداً `i` وتُنفذ دوال رد النداء بعد انتهاء الحلقة. يحل استخدام `let` المشكلة بإنشاء رابط جديد في كل تكرار فيطبع 0، 1، 2. وقبل ES6 كنا نستخدم الـ IIFE لإنشاء نطاق جديد."
- الفخ الشائع: القول بأن "`setTimeout` مع 0 مللي ثانية تُنفذ فوراً". هذا غير صحيح، فهي تنتظر حتى يفرغ مكدس الاستدعاءات عبر الـ Event Loop.‏
- الممارسة الهندسية الفضلى: اعتمد `const` كخيارك الافتراضي لأنها تعبر عن القصد بوضوح وتمنع إعادة التعيين العرضي. واستخدم `let` فقط للعدادات والقيم المتغيرة، مع فرض ذلك عبر أدوات التدقيق (Linters) مثل `prefer-const` و `no-var`.‏
